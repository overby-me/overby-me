# Worked trace: RUSTSEC-2021-0130 (`lru` use-after-free)

Status: **design validation + spec for integration test `corpus/lru-0130`.**
Written before implementation, deliberately: the cheapest time to find a design
flaw is while fixing it costs an edit.

## The bug

`LruCache` is a `HashMap<K, Box<LruEntry<K,V>>>` plus a doubly-linked list
threaded through the boxed nodes via `*mut LruEntry`. `iter()` yields `&K`/`&V`
borrowed out of those nodes. Reproducer (upstream issue jeromefroe/lru-rs#120,
`lru` 0.6.6 / 0.7.0):

```rust
let mut cache = LruCache::new(100);
cache.put(1, String::from("Hello world"));
cache.put(2, String::from("How are you?"));
cache.put(3, String::from("It's a great day!"));
for (key, value) in cache.iter() {
    cache.pop(key);          // removes entry -> drops Box -> frees node
    println!("{}", value);   // reads through a reference into freed memory
}
```

Advisory: use-after-free reachable from safe code (`iter`/`iter_mut`), patched
in 0.7.1. The borrow checker cannot see the aliasing because it launders
through a raw pointer.

## Trace under `--harden=case`

Table state notation: `id=N (base,len,epoch)`.

| # | Program event | Fe-C action | Table |
| - | ------------- | ----------- | ----- |
| 1 | `put` ×3 allocates `Box<LruEntry>` (+ `String` payloads) | interposed allocator registers each allocation | `id=N (b,len,epoch=1)` live, per node |
| 2 | `iter()` reborrows `*mut LruEntry` → `&V` | **§3.1 cast check**: `cementite::ensure(node_ptr, size_of::<LruEntry>())` | node live, epoch matches → **passes** (correct: no false positive) |
| 3 | `pop(key)` removes from map → drops `Box` → `free` | interposed `free` **bumps the epoch** and quarantines the address | `id=N` now dead; address not reissuable |
| 4 | `println!("{}", value)` dereferences `&V` | **§3.4 dealloc-reachable re-check**: `pop` is on the may-free callgraph, so a re-`ensure` guards this deref | epoch mismatch → **abort**, report names the reborrow site in `iter()` |

Under `--harden=through`, step 4 traps without any callgraph analysis: the
dereference itself is checked against the live capability.

## Findings (these change the plan, not just illustrate it)

### F1 — §3.4 is load-bearing, not optional

The cast check at step 2 **passes**, correctly: the node is alive when the
reference is minted. The bug is caught *only* by the re-check after `pop()`.

A v0 that shipped only cast-site checking — the "obvious" SafeFFI core — would
miss this entire bug class (references minted while live, invalidated later
through an alias). Dealloc-reachable re-checking moves from "optional
temporal extra" to **required for v0 acceptance**.

### F2 — epoch-on-free + quarantine is the mechanism, not bookkeeping

If the `free` interceptor merely forwarded to the real `free`, step 4 would
find either stale-live metadata or, worse, a *fresh valid* capability after the
allocator reissued the address (classic ABA). Two invariants become
non-negotiable in `cementite`:

- `free` bumps the allocation's epoch **before** releasing memory;
- freed addresses go through quarantine so a new allocation cannot present a
  valid capability at the same address while stale references exist.

This is the concrete justification for I2 (never-recycled IDs + liveness
epochs) — it is what makes temporal safety work at all.

### F3 — single-thread soundness, stated where it bites

This reproducer is single-threaded, so `case` catches it. Had another thread
freed the node between the re-check and the dereference, `case` could still
miss it — the free-during-scope thread-safety caveat. `through` mode is the
only fully thread-safe answer because it checks the access itself.

Document this in the README threat model in exactly these terms; do not let
"catches RUSTSEC-2021-0130" imply "catches concurrent UAF".

### F4 — false-positive pressure lives at step 2

Every live-reference mint pays a check. lru's `iter()` is a hot path; if the
per-check cost is not ~single-digit ns, iteration-heavy crates will show
badly. Micro-probe of the table design (dense radix, bounds + liveness):
**~2 ns/check** warm-cache single-thread — a floor, not a promise, but the
shape is right.

## Integration test spec (`corpus/lru-0130`)

- **Fixture**: vendored `lru` 0.6.6 (pinned, offline) + the reproducer above.
- **Assert (case)**: process aborts, non-zero status, report contains the
  freed allocation id, the free site (`pop`), and the reborrow site in
  `iter()`.
- **Assert (through)**: process aborts at the `println` dereference.
- **Assert (control)**: same program against `lru` 0.7.1 runs clean under both
  modes — a patched-version false-positive guard.
- **Assert (baseline)**: uninstrumented build is UB/segfault-prone; used only
  to show the delta, not as a pass/fail gate.
- Runs as a `nix flake check`, pure and offline via `nix/lib/cargo` vendoring.

## Follow-on traces worth doing before coding

1. A **spatial** bug (e.g. `SmallVec::insert_many` under-allocation) — should
   be caught at the cast/derive site, exercising a different path than F1.
2. A **cross-language** bug (rusqlite/libsqlite3 or xcb) — exercises FFI
   prologue checks and the "pointer loaded from memory" case.
3. A **stack UAR** case — exercises the post-call return-value re-check.
